## 결정

기존 빠른1:1/봇·초대 방·데일리는 유지하고, 공개 방 목록과 초대 전용 방을 가진2~4명 개인전을 추가한다. 첫 완주자가 서버 전이에서 확정되는 즉시 전체 판을 종료하고, 다른 정상 참여자는 그 시점의 opened_safe로 순위를 정한다. 시간 만료 때도 opened_safe를 사용하며 동점은 공동 순위다. 무작위 상대 한 명에게 기존의 검증된 숫자 조작을 적용하고, 지목 반사는 해당 overlay의 원래 source에게만 돌아간다.

공개 방 찾기/생성/초대 참가 → 대기실 → 각자 준비 → 방장 시작 → 서버 준비·countdown → 대전 → 결과 → 같은 방 대기로 돌아오는 반복 구조다. 라운드 ID/좌석은 매번 새로 고정하며 새로운 보드를 사용한다. 방의 수명과 매치의 수명을 분리한다.

1:1 전용 배열/Seat.other를 단순 확장하거나 pairwise 가짜 매치를 합성하지 않는다. Rust RuleEngine의 플레이어 집합과 전이/증명/시각을 하나로 일반화하고, v1 1:1/local API는 호환 어댑터로 유지한다. v2 다인전 DTO는 Rust에서 생성하고 클라이언트가 규칙·순위·공격 대상을 계산하지 않는다.

## 불변 조건

- 모든 참여자에게 같은 검증된 정답/zero opening, 각자의 PlayerBoard·knowledge·두 lie 총량. 정답/seed/다른 사람 셀은 전송하지 않는다.
- 자신의 계정 외 중복 점유 금지, 현재 room revision/role/세션과 시작 권한을 서버에서 검증한다. 초대 코드는 인증 수단이 아니다.
- live 라운드는 새 사람을 끼워 넣지 않는다. 공간이 있으면 다음 판 대기로만 참가한다. 기존 좌석 번호를 현재 라운드의 다른 사람에게 재사용하지 않는다.
- 재접속/철회·시작 실패·동시 이탈·장애 abort·정확히 한 번 저장·90일 보존/삭제를 N명으로 검증한다.
- 8언어·키보드/모바일·파일 다운로드 없음·방/대기/대전/결과 광고0·실제 운영 입력 분리를 유지한다.

## 영향과 한계

공개 방 metadata·참가자 게임 닉네임·N인 결과·방장 이전/같은 방 재대결이 새 범위다. 공개 방 자유문구는 짧은 평문만 허용하고 기존 닉네임 정책/신고·운영 경계를 재사용한다. 실시간 채팅·타인 보드 관전·팀전·생명/탈락제·랭크·유료 기능은 이 결정에 포함하지 않는다.

기존2인 코어/actor/저장/UI의 실제 변경과 회귀 검사가 필요하다. 문서 채택은 다인전 공정성·성능·재미 입증이 아니다. 설계 기록 PR 병합·#244 종료 뒤 하위 제품 이슈를 순차 구현한다. 사용자의 기존 리뷰·검사·병합 위임을 유지하며 추가 승인을 반복 요구하지 않는다.
