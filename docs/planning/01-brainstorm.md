## 0. 시장 현실 점검 (2026년 10월 기준)

| 분류 | 대표작 | 시사점 |
|---|---|---|
| 로그라이크 + 아이템 | DemonCrawl(2019), BroomSweeper(26.01), Roguesweeper(26.03), MineSweeper.R(26.03), Minesweeper Ultra Turbo Deluxe(26.04), Infinity Sweeper(26.05) | **2026년에만 5개 이상 출시된 레드오션.** "지뢰찾기 + 아이템 + 로그라이크"만으로는 차별화 불가 |
| 퍼즐 변형 | 14 Minesweeper Variants (97% 긍정, 리뷰 1,600+) | 하드코어 논리 퍼즐 수요는 확실히 있음. 품질 기준이 높음 |
| 같은 판 경주형 PvP | Minesweeper Together(2025), Minesweep Together(2026, 로컬), minesweeper.online, Minesweeper Battle Arena(모바일) | "누가 먼저 깨나" 레이스는 이미 있음 |
| 공격형 PvP | Minesweeper Battle Clash RPG(모바일), Sweeper Depon(itch) | 시도는 있으나 **PC/웹 대표작 부재** → 빈자리 |

**결론:** "아이템"과 "실시간 대전"은 각각은 흔하다. 차별화는 *무엇을 가지고 싸우는가*에서 나와야 한다.
지뢰찾기는 본질적으로 **정보 게임**(숫자 = 정보)이므로, **"정보를 조작하고 간파하는 대전"**을 핵심 축으로 제안한다.

---

## 1. 기회 정의

- **제품 콘셉트:** 짧은 판(2~4분)의 실시간 대전 지뢰찾기. 내 판을 풀면서 얻은 자원으로 상대 판의 정보를 오염시키고, 상대의 오염을 논리로 간파해 반격한다.
- **타깃 세그먼트:**
  1. 캐주얼 웹 유저 (CrazyGames/Poki 유입, 1판 단위 소비, 광고 수용)
  2. 퍼즐 코어 유저 (14MV/DemonCrawl 구매층, 실력 경쟁·랭킹 원함)
  3. 스트리머/친구 그룹 (방 코드로 즉시 대결, 관전 재미)
- **유저가 원하는 것:** 지뢰찾기의 "논리로 확신하는 쾌감" + 사람을 이기는 쾌감. 운(50:50 찍기)으로 지는 것은 극도로 싫어함.

## 2. 관점별 아이디어 (각 5개)

### 🧭 PM — 시장 적합성 · 차별화 · 수익

1. **거짓말 지뢰찾기(Liar Sweeper) 대전** — 공격 = 상대 판의 숫자 일부를 ±1 거짓으로 바꾸기. 방어 = 논리 모순을 찾아 "거짓 지목" → 맞히면 공격 반사, 틀리면 페널티. *다른 게임엔 없는 핵심 훅.*
2. **스위퍼 99 (배틀로얄)** — 테트리스 99 구조: 30~99명이 각자 판을 풀고, 연속 정답 콤보로 타겟에게 공격 전송. 검증된 장르 공식을 지뢰찾기에 이식.
3. **데일리 시드 + 공유 결과 카드** — 워들식. 전 세계 같은 판, 결과를 이모지 그리드로 공유. 웹 바이럴 + 매일 재방문(광고 노출).
4. **웹 무료(광고) → 스팀 유료 "완전판" 깔때기** — 웹은 1v1·데일리만, 스팀($4.99)은 배틀로얄·랭크·커스텀 룰·레벨 에디터. 웹이 스팀의 무료 마케팅 채널이 되도록 설계.
5. **비대칭 모드: 폭탄마 vs 탐지자** — 한 명은 지뢰를 배치(단, "논리로 풀 수 있어야 함" 제약), 한 명은 푼다. 라운드 교대. 친구끼리 심리전 + 스트리머 콘텐츠.

### 🎨 디자이너 — 경험 · 온보딩 · 몰입

1. **30초 튜토리얼 대전** — 첫 판은 봇 상대로, 공격 1회·거짓 간파 1회를 강제로 경험시키고 바로 승리. 규칙 설명 텍스트 최소화.
2. **"확신 표시" UI** — 거짓 숫자가 의심되면 칸을 길게 눌러 "?" 표시, 모순이 생기면 해당 숫자들이 은은하게 붉어지는 보조 시각화(난이도 옵션으로 끄기 가능).
3. **지뢰를 밟아도 즉사 X → 3초 기절 + 칸 잠금** — 대전에서 한 번 실수로 끝나면 이탈률 폭증. 회복 가능한 실패로 긴장 유지.
4. **관전/리플레이 하이라이트** — 거짓 간파·역전 순간을 자동 클립(짧은 GIF/영상) → 공유 버튼. 스트리머 친화.
5. **코스메틱 테마 (AI 이미지 활용)** — 판 스킨, 지뢰 이펙트, 깃발 디자인. 게임성에 영향 없는 것만 → P2W 논란 회피, 스팀 DLC/웹 광고 보상으로 해금.

### ⚙️ 엔지니어 — 기술 혁신 · 플랫폼

1. **노게스(No-Guess) 판 생성기 + 솔버 (Rust → WASM)** — 대전의 공정성 보장 필수 요소. 서버·클라이언트 동일 코드. 거짓 숫자 주입 후에도 "모순으로 간파 가능한가"를 솔버가 검증 → 공격이 운이 아닌 실력 싸움이 됨.
2. **결정론적 시드 + 서버 권위 검증** — 판은 시드로만 전송, 클라이언트 입력만 서버가 검증. 대역폭·서버비 최소, 치트 방지.
3. **Cloudflare Workers + Durable Objects로 방(room) 관리** — 방 1개 = DO 1개, WebSocket 유지. 유휴 시 비용 거의 0 → "손해 안 보기" 조건에 최적. 트래픽 터지면 그때 확장.
4. **봇 매칭 백필** — 초기 동시접속자가 적을 때 솔버 기반 봇(실력 단계 조절)이 빈자리 채움. 멀티플레이 게임의 최대 사망 원인(매칭 대기)을 해결.
5. **단일 코드베이스 웹 + 스팀** — TypeScript + PixiJS(or Phaser) + Rust WASM 코어 → 웹 배포, 스팀은 Tauri로 래핑 + Steamworks(업적·클라우드 저장·친구 초대). 언리얼 불필요.

## 3. 우선순위 Top 5

평가 기준(신규 제품 가중치): 핵심 가치 전달 40% · 검증 속도 35% · 차별화 25%

| 순위 | 아이디어 | 핵심가치 | 검증속도 | 차별화 | 비고 |
|---|---|---|---|---|---|
| 1 | 노게스 생성기 + 솔버 (Rust/WASM) | ★★★ | ★★★ | ★★ | 모든 것의 기반 |
| 2 | 거짓말 지뢰찾기 1v1 대전 | ★★★ | ★★ | ★★★ | 핵심 훅 |
| 3 | 봇 매칭 백필 | ★★★ | ★★★ | ★ | 1번 재사용 |
| 4 | 데일리 시드 + 공유 카드 | ★★ | ★★★ | ★★ | 웹 유입·리텐션 |
| 5 | 웹(광고) → 스팀(완전판) 깔때기 | ★★ | ★★ | ★★ | 수익 구조 |

> 배틀로얄(스위퍼 99)과 비대칭 모드는 **2단계 후보**. 1v1에서 "거짓말 공격"이 재미있다는 게 검증된 뒤 확장.

### 각 아이디어의 근거와 검증할 가정

**1. 노게스 생성기 + 솔버**
- 근거: 대전에서 50:50 찍기로 지면 유저는 게임을 "운빨"로 규정하고 떠남. 솔버는 봇·거짓말 검증·데일리 퍼즐에 모두 재사용.
- 가정: (a) 16×16/40지뢰 노게스 판을 100ms 안에 생성할 수 있다. (b) 노게스 판도 충분히 어렵고 지루하지 않다.
- 검증: Rust 프로토타입 벤치마크 1~2일.

**2. 거짓말 지뢰찾기 1v1**
- 근거: 기존 공격형은 "장애물 추가"(물량 공격) 수준. 숫자 자체를 속이는 공격은 지뢰찾기의 본질(정보)을 건드려 **설명 한 줄로 차별화가 전달됨**: *"상대에게 거짓말을 하는 지뢰찾기."*
- 가정: (a) 거짓 숫자 간파가 2~4분 판 안에서 재미있는 긴장을 만든다(너무 어렵거나 너무 쉽지 않다). (b) 캐주얼 유저도 30초 튜토리얼로 규칙을 이해한다. (c) 거짓말이 "불공정"하게 느껴지지 않는다.
- 검증: 로컬 2인 프로토타입 → 지인 5~10명 플레이테스트. 지표: "한 판 더?" 비율, 첫 판 이탈률.

**3. 봇 매칭 백필**
- 근거: 인디 멀티 게임은 출시 2주 후 동접이 급감 → 매칭 실패 → 리뷰 폭락. 봇은 이를 막는 보험.
- 가정: 유저가 봇인지 크게 개의치 않는다(혹은 봇 표시해도 플레이한다).
- 검증: 웹 출시 후 봇전/사람전 리텐션 비교.

**4. 데일리 시드 + 공유 카드**
- 근거: 개발비 거의 0(솔버 재사용), 매일 재방문 = 광고 노출 증가, SNS 공유 = 무료 마케팅.
- 가정: 지뢰찾기 결과도 워들처럼 공유할 동기가 생긴다(시간·실수 수·거짓 간파 수).
- 검증: 공유 버튼 클릭률 ≥ 5%.

**5. 웹 → 스팀 깔때기**
- 근거: 스팀 등록비 $100만 리스크. 웹 포털(CrazyGames/Poki)에서 무료로 재미·리텐션 검증 후 스팀 출시 → 손해 최소화. 웹 유저를 스팀 위시리스트로 전환.
- 가정: (a) 웹 포털 광고 수익이 서버비를 상회한다. (b) 웹 유저의 일부가 $4.99 완전판을 산다.
- 검증: 웹 출시 후 1개월 ARPDAU vs 서버비, 위시리스트 전환 수.

## 4. 기술 스택 의견 (언리얼에 대해)

**언리얼은 권장하지 않음.** 로열티 조건(매출 $1M 이후 5%)이 유리한 건 맞지만:
- 2D 퍼즐 게임에 비해 과도함 (빌드 용량·학습 비용·반복 속도)
- **웹 빌드를 공식 지원하지 않음** → 웹 광고 전략과 충돌
- 바이브코딩 생산성은 TS/Rust 쪽이 압도적

**권장:** TypeScript + PixiJS(렌더) · Rust→WASM(판 생성/솔버/검증, 서버·클라 공유) · Cloudflare Workers + Durable Objects(실시간 방) · Tauri(스팀 래핑) · AI 이미지(테마/코스메틱).
이미 써본 기술 위주라 학습 비용이 거의 없음.
