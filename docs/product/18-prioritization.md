# 18. MVP 우선순위

> 적용: pm-execution:prioritization-frameworks · 입력: [Stories](17-stories.md)

요구 범위는 MoSCoW로, 실행 순서는 의존성과 리스크로 판단한다. 데이터가 없는 RICE의 도달 수를 만들어 점수를 채우지 않는다. 고객 문제의 Opportunity Score는 사용자 중요도/만족도를 관측한 뒤 적용한다.

| 분류 | 범위 / 이유 |
|---|---|
| Must | FR01~16, 공정성·서버 권위·8언어·정책·광고 무차단·운영 복구. 핸드오프의 MVP 계약 |
| Should | 결과 설명 개선, 느린 기기 옵션, 닉네임 신고 처리 안내. 필수 흐름 이후 |
| Could | 추가 보드 테마·온보딩 영상. 일정 여유와 별도 이슈 |
| Won't this release | 스팀·포털·유료 클라우드·결제·배틀로얄·랭크·리플레이 공유·보상형 광고 |

## 실행 순서

1. 문서 검토와 설계 승인(M0).
2. 코어 경계·노게스·간파 증명(M1). 기술 위험이 가장 크다.
3. 오프라인 봇·튜토리얼·데일리·8언어 UI(M2). 핵심 가치를 먼저 관찰한다.
4. 게스트·서버·방·빠른 대전·재접속·순위(M3).
5. CMP·정책·SEO·광고(M4). 광고 승인 전 SDK 활성화하지 않는다.
6. 홈서버 배포·복구·용량 검증(M5), 베타와 튜닝(M6).

각 Must가 한 PR에 모두 들어가는 것은 아니다. 하나의 관찰 가능한 행동과 작은 인수 조건 묶음으로 이슈를 쪼갠다. 필수 기능을 일정 때문에 빼려면 PRD와 사용자 승인부터 변경한다.

## 결정 사항

가장 위험한 공정성을 먼저 검증하며 광고는 재미·게임 상태가 안정된 뒤 연결한다.

## 열린 질문

주당 작업량이 확인되면 Must 이슈의 크기를 재추정한다.
