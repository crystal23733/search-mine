# 21. 결과 중심 로드맵과 스프린트

> 적용: pm-execution:outcome-roadmap + sprint-plan · 입력: [우선순위](18-prioritization.md), [지표](20-metrics.md)

아래 일정은 추정이며 고정 출시일이 아니다. 1인 주 20시간 가정, 1주 계획창 16시간 작업+4시간 불확실성 여유. 이력을 측정하기 전 velocity·story point를 만들지 않는다. 한 이슈는 보통 1~3일 규모로 나눈다.

## 초기 실행창

- S1: 개발 도구/공유 타입 6h + 결정론·Board 경계 10h, 여유4h. 목표: 같은 입력을 native/WASM에서 재현.
- S2: 노게스 생성·솔버의 첫 행동 묶음 16h, 여유4h. 목표: 검증된 작은 판을 풀 수 있음. 큰 판 성능은 후속 이슈.
- S3: 간파 증명과 규칙 경계 16h, 여유4h. 목표: 반례를 검출하고 공격을 거절. 완료하지 못하면 M1 창 연장.

각 창은 추정이 크면 더 작은 이슈로 나누고 미완료를 자동 약속하지 않는다. M1 공정성, M3 권위·재접속, M4 외부 승인, M5 홈서버 사양이 주요 병목이다. 외부 가입과 모집은 사용자 담당이다.

## 작업 운영

[백로그](../workflow/backlog.md)의 선행 이슈부터 하나씩 진행한다. 완료→검증→PR→사용자 리뷰→병합→이슈 종료→다음 이슈 순서를 유지한다. **PR 작성은 승인이고 PR 리뷰를 대신하지 않는다.** main은 선택적 릴리스 용도이며 기본 브랜치는 계속 develop이다.

## 결정 사항

M0 승인 전 M1 작업과 스파이크를 시작하지 않는다. 문서 변경이 생기면 추적표와 백로그를 같이 갱신한다.

## 열린 질문

주당 시간, 홈서버 사양, 테스트 기기, 번역 검수 가능 인원은 사용자 확인 후 조정한다.
