# #167 · 다음 행동이 먼저 보이는 튜토리얼

FR08/11·NFR01/02/05/06/08 · TS13/18/19/20/26/30 · [ADR0079](../adr/0079-action-first-tutorial.md).

사용자의 한국어 실제 화면에서 긴 기초 설명 뒤에 과제/버튼이 밀리고 보드의 C3가 보이지 않는 것을 확인했다. 설계/시나리오를 먼저 갱신했다. 실행한 Red/Green·브라우저 결과와 한계는 검증 뒤 기록한다. 실제 사람의 이해·30초 성취는 #27의 관찰이며 자동 검증으로 대체하지 않는다.


## 실제 검증

설계·시나리오를 먼저 갱신한 뒤 단위 검사에서 버튼이 기초 설명 뒤에 있는 Red1개를 확인했다. 실제 Chromium PC/360px 모바일에서도 첫 버튼의 viewport 비율0으로 Red2개를 확인했다. 처음 브라우저 검사는 sandbox의 loopback listen 제한과 시험 Chromium 미설치로 실행되지 않았으며 이 환경 실패를 제품 Red로 계산하지 않았다. Chromium 설치 뒤 실제 제품 실패를 별도로 확인했다. 원자료는 gitignore 대상 `.tmp/tutorial-guidance/`에 보존한다.

Green에서 단위366개/49파일과 line3389/3701=91.56%를 확인했다. 번역 계약은 한국어의 같은 보간 변수 중복을 발견해 한 번만 사용하도록 고친 뒤 통과했다. 최종 실제 WASM 튜토리얼·3난이도 봇·공통 보드 PC/mobile18개를17.4초/retries0으로 확인했다. 첫 버튼이800px 높이의 화면 안에 모두 들어오고 기초 설명보다 먼저 나오며, 대상 좌표 배지/현재 단계/초기 선택이 같은 칸을 가리키는지 검사했다. 공격 단계 표시 제거·열기/지목 대상 이동·완료 제거·replay 복원·직접 click/touch·wrong action 거절·초대/return 복귀·8언어360px 모드 텍스트/위치 안내·키보드/긴누름/끌기/확대 동작을 검증했다.

PC/모바일 실제 산출 화면을 캡처해 검토했다. 최초 캡처에서 기본 선택 A1과 목표 C3가 모두 강조되는 혼동을 찾아 expected 대상이 바뀔 때 키보드 선택도 맞추되 사용자 초점을 강제로 옮기지 않도록 보완했고 해당 보드/브라우저 검사를 다시 통과했다. 실제 Brave의 최초 사용자 화면은 읽기 전용으로 확인했다. 이후 native UI 확인 도구는 응답 지연 뒤 비활성 오류로 끝났으며, 변경 후 검증 근거는 Playwright의 실제 Chromium과 모바일 에뮬레이션이다. 실제 휴대폰이나 사람이 이해했다는 검증으로 표현하지 않는다.

## 코드 리뷰와 한계

TutorialPage는 공개 expected의 cell로 위치/좌표만 표현하고 도메인 전환은 기존 controller/Rust에 맡긴다. 공통 Board/Cell의 선택적 hint는 튜토리얼에서만 주입하고 일반 대전·데일리에는 정답 표시가 생기지 않는다. CSS는 tutorial-layout 안에 한정하고 기존 native details의 상태·locale/replay·skip/완료 저장을 유지한다. 공유 한국어도 읽기 쉽게 고치되 봇은 컴퓨터 상대임을 명시한다. 리뷰에서 mistakes가 지뢰 열기뿐 아니라 틀린 지목도 포함함을 실제 Rust로 확인해 ‘지뢰를 누른 횟수’로 좁혀 쓰지 않도록 고쳤다. 키보드/터치 도움말의 기존 대체 조작도 유지했다.

선행 #168/PR170은 lock/생성 선언의 최신 WASM 정합성을 별도 검증해 develop a674fc8에 병합·CLOSED했다. 이 UI 변경에는 사용자가 남긴 Windows lock 참조6곳을 포함하지 않는다. 외부 OAuth/CMP·광고·SW #83·운영 배포·실제 사람의 이해/30초 목표는 이 변경의 출구가 아니다. 원격 검사와 병합 상태는 PR 및 로컬 일별 리뷰에서 확인한다.

최종 lint/typecheck/format과 번역 계약, 문서217개/제품21개/설계18개/시나리오36개, Mermaid34개/오류0 및 diff 공백 검사를 통과했다. 전체 production build와 WASM/fixture freshness는 선행 호환성 확인 과정에서 실행했으며 최종 commit의 깨끗한 전체 build/실DB 검사는 CI에서 별도로 확인한다.
