# #245 다인전 코어 검증

FR02~05, FR14/15/18과 TS40/41/45를 다룬다. [다인전 설계](../design/20-multiplayer-rooms.md)의 승인 기록은 PR #250에 병합됐다.

기존 `RuleEngine`과 새 `RaceEngine`은 같은 Rust 전이를 사용한다. 새 코어는 검증된 동일 판에서 2~4개의 개인 관측을 만들고, 기존 방의 시작 준비와 실제 시작 시각을 분리한다. 한 사람에게 상대들의 요약만 제공하며 상대의 셀·정답·공격 위치와 대상 추첨 결과를 내보내지 않는다.

공격 시 아직 참가 중인 다른 사람 한 명을 균등 추첨한다. 편향되는 난수 샘플은 최대 8회까지만 거절하고 다시 읽는다. 한 상대를 선택하면 기존 숫자 조작 증명을 적용한다. 후보가 없거나 거짓말이 이미 두 개면 게이지를 보존한다. 명령을 재전송해도 원래 추첨과 응답을 사용한다.

첫 완주 전이가 전체 판을 끝내고, 그 시점의 열린 안전칸 수와 순위를 고정한다. 동점은 공동 순위다. 이탈 후 복귀가 만료된 참가자는 순위에서 제외한다. 같은 시각에 여러 유예가 끝나면 모두 처리한 뒤 승자를 결정한다. 마지막 한 명도 아직 재연결 중이면 돌아오거나 유예가 끝날 때까지 기다린다. 시작 전 취소와 서버 중단은 순위를 매기지 않는다.

## 검사

- 새 코어 사례를 먼저 작성해 해당 API가 없는 실패를 확인했다. 최소 구현 후 6개가 통과했다.
- 새 대전에서 상대의 연결 상태가 바뀌어도 공개 revision이 변하지 않는 결함을 실패로 확인하고 수정했다. 세 번째 공격을 검사하는 작은 판에서는 마지막 칸을 연 순간 경기가 끝나도록, 두 번째 거짓말 뒤에 지목을 보내던 시험 순서를 바로잡았다.
- 최종 다인전 테스트 14개가 통과했다. 같은 판과 관측 분리, 공동 순위와 종료 후 입력, 실제 다중 공격과 반사, 추첨 실패 및 중복 명령, 재연결 유예, 이탈 후 기존 숫자 복원, 늦은 증명과 시작·취소 경계를 검증했다.
- Rust 전체 작업공간, Clippy, WASM 확인, 기존 선언과 native fixture 검사 결과는 연결 PR에서 기록한다. 방 탭, 권위 서버·실DB·WS, 실제 브라우저 다인전은 #246~249에서 검증한다.
