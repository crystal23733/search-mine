# #246 공개·초대 방 정책과 Rust v2 계약

FR01/07/17과 TS37~39/42/43/45의 순수 방 정책을 구현한다. [설계20](../design/20-multiplayer-rooms.md)과 PR #251의 다인전 코어를 바탕으로 한다.

공개 목록에는 제목과 인원, 정원, 진행 상태, 참가 가능 여부를 표시한다. 한 페이지는 최대 20개다. 실제 참가자는 인증을 거친 뒤 방 상태를 받을 수 있다. 초대 코드는 방 목록에서 빠지며 기존 8문자 형식을 공유한다. 방 이름에는 기존 닉네임과 같은 문자 검사를 적용하고 길이만 확장한다.

모든 참가자가 준비하면 방장이 시작을 예약할 수 있다. 준비 중 변경, 시작 전 취소, 늦은 보드 완료의 경계를 구분한다. 현재 방 revision은 오래된 준비·설정·추방 명령을 거절한다. 참여자와 경기 좌석은 시작 시 고정하며 중간 참가나 재입장은 다음 판을 기다린다. 방장 이탈 시 먼저 들어온 참가자가 권한을 받는다. 결과 뒤 같은 방에서 다시 준비할 수 있다.

## 실행 근거

- v2와 방 정책 사례를 먼저 작성했다. 계약과 카운트다운 단계가 없을 때 컴파일 실패를 확인했다.
- 로컬 방 정책 9개, v2 명령 검사 2개를 통과했다. 공개 목록·20개 페이지·초대 방·입력 검증·정원·방장 승계·준비 취소·카운트다운 실패·같은 방 다음 경기·재입장과 좌석 구분을 확인했다.
- Rust 선언을 생성한 뒤 최신 파일을 비교했다. 로컬 방 정책 줄 커버리지는 524/540(97.04%)였다. 기존 서버 검사에도 방 정책의 95% 기준을 추가했다.
- 다음 단계에서 같은 계정의 기존 큐와 다인 방 입장을 직렬화한다. 실행 서버의 세션 재검사, 요청 ID 중복 처리, WS/DB 결과 및 복구, 공개 방 HTTP와 브라우저를 연결해 검증한다.
