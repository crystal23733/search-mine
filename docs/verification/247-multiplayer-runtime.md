# #247 다인 방 서버 실행과 결과 복구

FR01/02/07/14/16~18, TS37~43/45를 [다인 방 설계](../design/20-multiplayer-rooms.md)와 [ADR0110](../adr/0110-multiplayer-rooms-and-rankings.md)에 따라 서버에 연결한다.

## 입장과 경기 시작

- 기존 빠른 대전과 다인 방이 참가 점유를 공유한다. 현재 로그인 세션에서 같은 요청을 다시 보내도 입장과 준비가 반복되지 않는다. 이탈한 계정에는 기존 응답의 방 정보와 초대 코드를 다시 제공하지 않는다.
- 경기 하나와 참가자 전원의 연결 자리를 한 번에 예약한다. 보드 계산과 DB 등록 뒤 고정된 라운드, 좌석, 권한을 확인하고 그때부터 라운드 ID를 공개한다. 초기 연결이 빠지면 예약을 취소하고 그 방에서 다시 준비할 수 있다.
- 버전2 방 HTTP의 공개 목록과 현재 세션의 명령을 검증한다. WebSocket은 서버가 좌석을 부여하며 각 참가자에게 자신의 판과 상대 요약만 보낸다. 명시 이탈과 세션 철회, 전송 연결의 재접속 유예를 별도 시나리오로 다룬다.

## 결과와 복구

- 기존 PostgreSQL 마이그레이션을 유지하고 순방향 마이그레이션을 적용한다. 시작 시각과 확정 인원, 순위를 저장한다. 삭제된 참가자 행은 재시도에서 복원되지 않으며 남은 참가자의 공동 순위는 유지된다.
- 같은 쓰기 연결에서 결과와 필수 이벤트를 함께 확정한다. 현재 계정은 내 정보에서 자신이 참가한 경기의 인원과 순위, 이탈 여부를 확인할 수 있다. 시작 시각으로부터 90일이 지나면 조회에서 제외한다.

## 실행 근거

- 다인 권한, 방 서비스와 연결 예약, DB 기록, 버전2 메시지, 경기 실행기, HTTP에 각각 해당 동작이 없는 실패를 먼저 확인한 뒤 구현했다.
- 로컬 PostgreSQL 18.7과 실제 서버의 네 계정 TCP WebSocket으로 경기 시작, 본인 판과 상대 셋, 외부 계정 거절, 조작 ACK, 이탈과 다음 판 대기, 네 명의 결과·이벤트를 검증했다. 같은 방의 새 라운드에서 초기 연결이 빠지면 반영할 결과 없이 기다리는 상태로 돌아간다.
- 서버 프로세스를 종료한 뒤 재기동해 시작 시각을 보존한 장애 결과를 복구하고, 내 정보에서 미확인 순위와 통계를 `null`로 받는 것을 확인했다. 경기 실행기 테스트는 정상 종료 준비 중에도 진행 중인 판의 저장을 완료한다.
- 브라우저의 공개 방 화면과 8개 언어, 초대 후 OAuth 복귀, 다인전 조작과 재대결 UI는 #248과 #249에서 검증한다.
