## 적용 범위

위 지시를 변경된 요구사항에 따른 구현 시작 승인으로 기록한다. 제품 코드보다 먼저 OAuth/최소 정보·제공자 확장·화면 기준을 PRD/설계/ADR/TS에 반영한다. 그 외 기존 고정 규칙과 홈서버·Rust·8언어·광고 조건은 유지한다. 화면의 예시 숫자/문구가 규칙·보안·접근성 계약과 충돌하면 최신 명세를 따른다.

이는 알고리즘 공정성·목표 성능·법적 정책의 검증 완료를 의미하지 않는다. 특히 E4 거짓말 안전 증명은 여전히 출시 게이트다. 사용자 지시는 앞으로 작성할 코드 PR에 대한 사전 리뷰/병합 승인도 아니다.

## PR 병합 상태

자동 승인 검토는 2026-10-06 PR #29 병합을 거절했다. 이유는 개발 시작 지시와 해당 PR의 명시적 검토/병합 승인이 다르기 때문이다. 우회하지 않고 초기 설정 PR과 이 설계 수정 PR을 검증해 사용자에게 구체적인 병합 승인을 요청한다. 승인 기록 PR이 develop에 병합되기 전 #4 제품 구현을 시작하지 않는다.

## 2026-10-07 순차 작업·병합 위임

> 병합은 니가 진행하고 순차적으로 모든 작업 니가 끝내. OAuth키값같은거 필요할 때만 그부분만 패스하고 나중에 나에게 요구해. 추가적으로 필요한 라이브러리같은거 있을 경우 cargo add 명령어나 yarn명령어를 사용할 때 버전을 명시하지 않고 최신 버전을 유지해

이 지시로 #29/#30 및 이후 작업의 코드 리뷰·검사·병합·이슈 종료·다음 작업 진행 권한이 부여됐다. 앞 절의 병합 승인 대기는 해소됐으며 기존 스킬의 반복 사용자 승인 단계는 최신 지시로 대체한다. 키/외부 계정/실측 사용자 입력은 후속 확인 항목으로 분리하고 독립적인 구현을 중단하지 않는다. 테스트나 실측 결과를 만들지 않는다. 추가 명령에는 버전을 붙이지 않고 최신 안정 라이브러리를 받되 실제 해결된 버전은 lockfile로 보존한다.


## 2026-10-18 패키지 관리자 교체

> yarn으로 교체

최신 사용자 지시에 따라 pnpm을 Yarn으로 교체한다. 기존 검토·검증·PR 병합 위임과 비밀/원문/로컬 준비 문서 보존은 유지한다. ADR0078과 #165에서 기존 선언 패치·지원 의존성·lockfile/CI 재현성을 검증하며 게임 규칙이나 외부 계정 준비 범위를 바꾸지 않는다.

## 2026-11-01 내 정보 중심 조회와 파일 다운로드 제거

사용자는 다음과 같이 설계 변경 필요성을 제기했다.

> 굳이 그걸 내보내기로 구현해야 하나? 일반적인 웹서비스들은 "내 정보"같은 페이지를 따로 구현한 뒤 본인의 전적, 본인의 설정같은걸 구현해놓잖아. 이건 설계를 변경할 필요성이 있을거같아

‘내 정보’에서 전적·계정·설정·동의 상태를 확인하도록 변경하면서 기존 파일 다운로드를 보조 기능으로 유지할지, 제거할지 질문했다. 사용자는 **“파일 다운로드 기능 제거”**를 선택했다.

이 최신 지시로 파일 다운로드를 유지하는 기존 설계와 동의 내보내기 후속 계획을 대체한다. [ADR0081](../adr/0081-my-info-and-export-removal.md)에서 내 정보·최근 보관 전적·계정/기기 설정·현재 동의 조회와 파일 UI/API 제거를 정의한다. #176 설계를 먼저 병합하고 #177 본인 조회 API→#178 화면 전환/파일 제거를 순차 검증한다. 기존 계정 삭제·최소 수집·권한/철회·보존 원칙과 전체 작업의 리뷰·병합 위임은 유지한다. 이 기록은 화면 구현이나 실제 OAuth/CMP 검수 완료의 증거가 아니다.
